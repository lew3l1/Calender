Политика конфиденциальности

Черновик для стартовой версии · обновлено 26 октября 2026 года

Перед публичным запуском владелец сервиса должен указать свои юридические контактные данные, применимое право, срок хранения и порядок обращений. Этот шаблон не заменяет юридическую проверку.

1. Какие данные обрабатываются

Calender обрабатывает адрес электронной почты и идентификатор аккаунта, который необходим для входа; созданные пользователем события, заметки и задачи; а также настройки push-уведомлений, если пользователь добровольно их включает. При входе через Google сервис получает базовые сведения профиля, которые предоставляет провайдер, например email и идентификатор.

2. Для чего используются данные

Данные используются для входа, восстановления доступа, синхронизации календаря между устройствами, показа собственных событий и задач, а также отправки напоминаний по явному согласию пользователя.

3. Где хранятся данные и кто имеет доступ

В облачном режиме записи хранятся в настроенном проекте Supabase. Политики Row Level Security должны ограничивать доступ к записям их владельцем. Подписка push хранит адрес конечной точки push-провайдера и ключи подписки, необходимые для доставки уведомлений. В демо-режиме календарь и задачи хранятся только в localStorage данного браузера и не синхронизируются.

4. Сторонние сервисы

Облачный режим может передавать технические данные Supabase для аутентификации и хранения, а Google — в случае входа через Google. Push-провайдер браузера получает push-сообщение при наличии подписки. Условия обработки этими сервисами регулируются их собственными документами.

5. Безопасность и сроки хранения

Сервис следует настраивать с HTTPS, RLS, подтверждением email, минимальными правами доступа и секретами только на сервере. Удаление аккаунта должно сопровождаться удалением связанных записей. Пока срок автоматического удаления не настроен, не вводите в календарь специальные категории чувствительных данных.

6. Ваш выбор

Вы можете не включать push-уведомления, отозвать разрешение в настройках браузера и использовать демо-режим без облачного аккаунта. В облачном режиме функции экспорта и полного удаления аккаунта должны быть добавлены владельцем сервиса до широкого запуска.

7. Контакт

Контакт владельца сервиса для запросов о данных будет опубликован здесь перед публичным запуском.
